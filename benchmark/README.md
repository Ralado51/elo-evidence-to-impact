# benchmark

The synthetic adversarial cases live in `api/benchmark/cases.json`, generated by
`api/benchmark/generate.py` (synthetic data only). The engine is `api/src/elo/benchmark.py`; run it with
`api/scripts/run_benchmark.py`.

- 77 cases, pt-BR and English, split `dev` / `eval` by a fixed hash. Tune rules and prompts on `dev` only; run `eval` once at the end.
- 46 easy cases (every verdict, negation, accents, mixed language) and 31 hard ones written to break the deterministic rules (goals, hypotheticals, another person, hand-guided help, two activities, cross-sentence).
- Labels come from how each case is constructed and are pending clinical review by the occupational therapist. A test checks that the labels agree with the verifier when extraction is perfect.
- Headline safety metrics: `unsafe_supported` (predicted supported, truth is not) and `false_contradicted`, plus a confusion matrix, extraction precision/recall and the abstentions.
- Baseline (rules, all splits): easy cases 100%, hard cases 0%; the hard failures are reported, not hidden.

## Rounds (generalization)

- **Round 1** hard cases (`hard-*`) were used to shape the prompt and the pack (exclusions for goals, hypotheticals, another person, failed attempts, hand guiding). Their results are optimistic.
- **Round 2** hard cases (`r2-*`) are new kinds of difficulty (almost achieved, temporal order, implicit setting, unlisted synonyms and report phrases, unlisted hand-guiding wording, claims dated before the note, progress over time). They were written after the tuning and nothing was changed for them. Look at `by_round` for the honest number.
- Known limits stay visible: report phrases outside the pack's cues (for example "segundo a avó") are read as direct observation by the rules; two activities in one sentence and level of help in a different sentence go to human review.
- Run the `eval` split once, at the end, with the rules and prompt frozen.

## Round 3 and what is now "seen"

After the second model run, round-2 failures (almost achieved, report phrases such as "segundo a avó") were fixed with deterministic markers, so round 2 is now **seen** too. Round 3 (`r3-*`) holds new kinds of difficulty (wishes, needs, a classmate, refusal, plans, unlisted synonyms and report phrases, unlisted physical help) written after those fixes and not used to tune anything. The rules alone are expected to fail most of them; the question is what the model and the consensus mode do. Look at `by_round.round_3_hard`.

## Round 4 (sealed)

`r4-*` cases are forced into `eval`, written after all fixes, and were never run during tuning. After the third model run, round 3 is also **seen** (the rules were extended for its failure classes: wishes, needs, a relative as subject, generic reporting frames, refusal, plans). The only unbiased number left is `eval`, to be run once at the end.

## Eval freeze

Extraction, pack, prompt and benchmark cases are frozen at commit `fa38c38` for the one-time `eval` run. Primary mode (decided before seeing eval): **consensus** with `qwen2.5:3b`; the model-alone mode is also run and reported. Any change to extraction code, pack, prompt or cases after this point makes the `eval` result invalid and requires saying so.

Dev result (59 cases): model alone 94.9% accuracy, 0 unsafe-supported, precision 0.92, recall 0.90. Consensus 84.7%, 0 unsafe-supported, precision 0.98, recall 0.81, 10 items sent to human review.

## Eval result (run once, frozen code `3efd0f6`, qwen2.5:3b, 24 cases)

| | Consensus (pre-registered primary) | Model alone |
|---|---|---|
| Verdict accuracy | 83.3% | 95.8% |
| Unsafe `supported` | 1 (`r4-02`) | 1 (`r4-02`) |
| False `contradicted` | 0 | 0 |
| Extraction precision / recall | 0.94 / 0.80 | 0.95 / 0.95 |
| Sent to human review | 7 | 0 |

- The only unsafe case is sealed `r4-02` ("... sozinho em casa, **diz a mãe**."): a trailing attribution the report cues do not recognize, so the code reads it as direct observation. Both modes share that code, so the consensus did not help.
- Consensus lost three legitimate cases (unlisted synonyms the rules cannot read); they go to review, which is the designed behavior.
- Reporting fix after the run: the `round` tag of the six `r4-*` cases was missing, so the run's `by_round` counted them under round 1. Case text, labels and split are unchanged (verified by diff); in that output the 8 "round 1" cases are 2 round-1 cases plus the 6 sealed ones.
- Nothing in the extraction code, pack or prompt was changed after this run.

## Post-eval fix and sealed round 5

- Fix after the eval (not measured on the original eval): attribution by verb before or after a known family/teacher noun ("diz a mãe", "conta a professora", "says the mother"). A therapist speaking to the patient ("a terapeuta disse a Davi") is not a report. New pack fields: `attribution_verbs`, `caregiver_nouns`.
- Round 5 (`r5-*`, 6 cases, forced into `eval`): written after the fix. Two use phrasing the fix does not cover on purpose ("Pelo que a vó contou", "de acordo com os vizinhos").
- Disclosure: when I generated the cases I ran the **rules-only** mode once on round 5 to check the file was well formed. Result: 5 of 6 right; `r5-03` ("Pelo que a vó contou") is read as direct observation, as designed. `r5-06` passed because the generic frame "de acordo com" already covers it, so it is less adversarial than I intended. Nothing was changed after seeing this. The model and consensus runs on round 5 are still unseen.
- Run only round 5 with `python scripts/run_benchmark.py --mode consensus --model qwen2.5:3b --split eval --only-round 5`. Rounds 1 to 4 keep their one-time result above.
- Default mode for the product: consensus (pre-registered). The model-alone numbers are reported next to it.
